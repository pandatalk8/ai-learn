# 课程全流程工作与问题清单

把课程当作一个完整产品来看，从调研、设计、生产、销售到持续运营，全部工作可以归纳为十类。

整体链路：

> 用户需求 → 课程定位 → 课程设计 → 内容生产 → 教学交付 → 发布平台 → 招生销售 → 学员运营 → 数据迭代 → 经营保障

## 一、用户与需求

解决“课程到底为谁服务”。

需要回答：

- 核心用户是谁？
- 用户的职业、技术基础、年龄和收入情况是什么？
- 用户现在处于什么阶段？
- 用户想实现什么具体结果？
- 用户以前尝试过什么？
- 最容易卡在哪一步？
- 每周能投入多少时间？
- 愿意为什么样的结果付费？
- 哪些人明确不适合这门课？
- 如何通过访谈验证，而不是靠想象用户画像？

主要产出：

- 用户画像。
- 用户访谈记录。
- 痛点优先级。
- 学习障碍清单。
- 适合与不适合人群说明。

## 二、课程定位与商业模式

解决“这是一门什么课，为什么值得购买”。

需要回答：

- 课程属于知识课、工具课、项目课还是训练营？
- 课程帮助用户从什么状态到什么状态？
- 最核心的课程承诺是什么？
- 哪些结果可以承诺，哪些不能承诺？
- 与免费教程、其他 AI 编程课有什么区别？
- 是录播、小班、陪跑，还是一对一？
- 按单期收费、永久买断还是会员订阅？
- 是否设置录播版、训练营版和陪跑版？
- 课程定价多少？
- 是否提供退款、延期、补课或复训？

主要产出：

- 一句话定位。
- 核心价值主张。
- 课程承诺与边界。
- 产品版本和价格体系。
- 退款及服务规则。

## 三、学习结果与课程架构

解决“学员到底要完成什么”。

需要回答：

- 结课时学员必须交付什么成果？
- 最小结课标准是什么？
- 哪些内容是主线，哪些是选修？
- 课程分几个阶段？
- 每个阶段的前置条件是什么？
- 章节顺序是否符合真实操作流程？
- 是否设置一个贯穿全课的参考项目？
- 学员自己的项目如何迁移？
- 每个阶段如何验收？
- 掉队后从哪里恢复？

主要产出：

- 课程地图。
- 课程大纲。
- 学习路径。
- 必修与选修清单。
- 阶段里程碑。
- 结课验收标准。

## 四、教学设计与授课形式

解决“怎么教，学员才真的能学会”。

需要回答：

- 采用录播、直播还是混合形式？
- 每节课多长？
- 一期持续多少周？
- 每周学习节奏是什么？
- 直播讲知识、演示操作还是诊断项目？
- 作业如何布置和批改？
- 谁来答疑，多久响应？
- 如何处理不同基础的学员？
- 如何降低学员的工具选择负担？
- 如何让 AI 承担代码检查、报错分析等重复工作？
- 怎样防止学员只看视频不动手？

主要产出：

- 授课日历。
- 每周学习流程。
- 直播和答疑安排。
- 作业制度。
- 陪跑与督学机制。
- 掉队恢复机制。

## 五、课程内容生产

解决“课程材料具体怎么做出来”。

需要回答：

- 哪些内容需要录制视频？
- 哪些内容适合文字教程？
- 哪些需要现场演示？
- 是否需要 PPT、讲稿、字幕和配图？
- 代码、模板、提示词放在哪里？
- 是否提供参考项目的阶段版本？
- 每章是否有作业、答案和验收清单？
- 平台界面发生变化后怎么更新？
- 模型、价格、政策等时效信息如何维护？
- 内容由谁编写、录制、剪辑和审核？
- 如何统一术语、案例和表达风格？

主要产出：

- 课程文稿。
- 视频和字幕。
- Slides。
- 代码仓库。
- 提示词模板。
- 作业与答案。
- 检查清单。
- 持续更新页。

## 六、平台与技术基础设施

解决“课程放在哪里，学员在哪里完成学习”。

需要回答：

- 视频课程发布在哪里？
- 直播使用什么平台？
- 作业在哪里提交？
- 代码和模板放在哪里？
- 社群和答疑在哪里进行？
- 学员通知通过什么渠道发送？
- 如何管理购买权限？
- 如何统计观看和完成进度？
- 如何保护课程内容和用户数据？
- 平台故障时有什么备用方案？
- 后续是否需要自己的课程网站？

主要产出：

- 平台组合方案。
- 课程店铺或课程页面。
- 社群和班级空间。
- GitHub 模板仓库。
- 权限与账号流程。
- 学员操作手册。

## 七、招生、营销与销售

解决“潜在用户如何知道、信任并购买课程”。

需要回答：

- 用户平时在哪里获取信息？
- 选择哪些主要获客渠道？
- 免费内容讲什么？
- 如何展示课程差异和最终成果？
- 是否做公开课、体验课或试听课？
- 课程详情页需要说明什么？
- 如何收集潜在用户线索？
- 招生周期多长？
- 是否设置早鸟价、共创价和正式价？
- 用户购买前最常见的疑虑是什么？
- 谁来咨询转化？
- 如何使用案例和学员成果建立信任？

主要产出：

- 招生策略。
- 课程详情页。
- 公开课。
- 宣传内容计划。
- 销售问答。
- 报名和支付流程。
- 招生数据漏斗。

## 八、学员服务与社群运营

解决“购买以后如何保证体验和完成率”。

需要回答：

- 学员入学时需要完成什么？
- 如何进行基础能力评估？
- 如何帮助学员确定项目？
- 开营、日常、结营分别做什么？
- 如何提醒上课和提交作业？
- 学员卡住后向谁求助？
- 如何整理高频问题？
- 是否组织项目互评、组队或演示日？
- 如何处理冲突、广告和违规内容？
- 学员毕业后是否继续保留社群权益？
- 如何收集并展示优秀项目？

主要产出：

- 入学问卷。
- 开营手册。
- 学员档案。
- 答疑知识库。
- 社群规则。
- 每周提醒。
- Demo Day。
- 毕业与校友机制。

## 九、数据、质量与课程迭代

解决“如何判断课程是否有效”。

需要回答：

- 有多少人报名、到课和完成作业？
- 学员主要在哪个章节掉队？
- 哪些作业最容易失败？
- 从报名到结课的完成率是多少？
- 有多少人真正发布了产品？
- 有多少产品被真实用户使用？
- 学员满意和不满意的原因是什么？
- 哪些内容应该删除、提前或补充？
- 每一期结束后如何复盘？
- 如何区分课程问题、学员投入问题和工具变化问题？

建议关注的核心指标：

- 报名转化率。
- 到课率。
- 作业提交率。
- 阶段通过率。
- 结课率。
- 产品上线率。
- 真实用户试用率。
- 退款率。
- 推荐意愿。
- 下一期复购或转介绍率。

主要产出：

- 课程数据看板。
- 每周运营复盘。
- 学员反馈报告。
- 内容修改清单。
- 下一期迭代计划。

## 十、团队、财务、版权与风险

解决“课程能否长期稳定经营”。

需要回答：

- 哪些工作由讲师完成？
- 哪些需要助教、剪辑、运营和客服？
- 每一期可以服务多少人？
- 每名学员的实际服务成本是多少？
- 平台、投放、剪辑和人工成本是多少？
- 收入、利润和现金流目标是什么？
- 课程素材、软件截图和案例是否可以合法使用？
- 学员项目和个人信息如何获得展示授权？
- 是否需要隐私政策、用户协议和退款规则？
- 如何处理盗版、投诉和支付争议？
- AI 生成内容和第三方代码如何审核？
- 讲师临时无法授课时有什么预案？

主要产出：

- 人员分工表。
- 课程预算。
- 单期利润模型。
- 服务容量上限。
- 用户协议。
- 版权与隐私规则。
- 风险应对预案。

## 第一阶段优先解决的问题

如果现在还处于课程规划期，不需要同时解决全部问题。第一期先完成以下五件事：

1. 访谈 10～15 名目标用户。
2. 明确一个可验收的结课结果。
3. 设计一条最短的课程主线。
4. 确定首期授课、作业和答疑形式。
5. 招募 15～20 名付费共创学员验证。

其中最重要的不是“录多少节课”，而是：

> 谁来学、想获得什么结果、通过什么过程完成，以及怎样证明他真的完成了。
