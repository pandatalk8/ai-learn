# 深度理解 LLM Agent 底层原理

> 知识范围：任务规划、Function Calling、MCP、RAG、向量知识库、长短期记忆、上下文工程、多智能体编排与评估。
>
> 本文为 AI 协助整理的学习大纲，尚未经过人工复核；参考资料用于支持基础概念，不表示全部条目已经逐项核验。

## 学习主线

理解 Agent 如何把用户目标转化为行动，利用外部知识与工具，根据反馈持续推进，最后验证任务是否完成。

目标输入 → 任务规划 → 工具与知识调用 → 观察反馈 → 更新状态与记忆 → 调整计划 → 验证交付

## 一、基础认知：从大语言模型到 Agent

### 1.1 LLM 的工作基础

- Token 与文本生成机制
- 上下文窗口与容量限制
- 指令遵循与结构化输出
- 语言理解、推理与幻觉
- 模型知识的时效性

### 1.2 Agent 的核心组成

- 模型：理解输入并判断下一步
- 指令：定义目标、约束与行为规范
- 工具：访问数据并执行外部操作
- 状态：记录任务进度与执行结果
- 记忆：保存可复用的信息与经验
- 执行循环：持续行动、观察与调整

### 1.3 架构边界

- 普通对话：根据输入生成回答
- 固定工作流：按照预定义路径执行
- 自主 Agent：由模型动态决定行动路径
- 不同架构的适用条件与成本

### 1.4 Agent 运行闭环

1. 接收目标
2. 判断下一步
3. 执行动作
4. 观察结果
5. 更新状态
6. 继续执行或结束任务

**核心问题：模型生成文本，如何变成系统执行任务？**

## 二、任务规划：把目标拆成可执行步骤

### 2.1 目标建模

- 输入与预期交付物
- 时间、成本和权限约束
- 成功标准与验收条件
- 模糊目标的澄清

### 2.2 任务分解

- 子任务粒度
- 任务依赖关系
- 顺序执行与并行执行
- 中间结果与检查点

### 2.3 规划方式

- 预先制定计划，再逐步执行
- 根据观察结果动态决定下一步
- 分层规划：整体目标、阶段任务、具体动作

### 2.4 常见模式

- ReAct：结合推理、行动与观察
- Plan-and-Execute：规划与执行分离
- 规划者与执行者分工
- 执行结果检查与计划修订

### 2.5 失败恢复与停止条件

- 信息不足时补充检索
- 执行失败时重试或切换路径
- 成功判定
- 最大轮数、时间与成本预算

**核心问题：计划由谁维护，执行偏离计划后如何恢复？**

## 三、Function Calling：模型如何使用工具

### 3.1 工具定义

- 工具名称与用途描述
- 参数 Schema
- 必填参数与类型约束
- 返回结果与错误格式

### 3.2 调用流程

1. 程序向模型提供工具描述
2. 模型提出工具调用及参数
3. 程序校验参数并执行工具
4. 程序返回执行结果
5. 模型根据结果继续判断

### 3.3 工具选择与参数生成

- 工具描述的清晰度
- 相似工具之间的区分
- 参数歧义与缺失信息
- 结构化输出与执行前校验

### 3.4 执行控制

- 串行与并行调用
- 超时与重试
- 幂等与重复执行
- 调用次数和成本限制

### 3.5 权限与错误处理

- 只读工具与写入工具
- 授权与敏感操作确认
- 参数错误
- 工具不可用
- 结果不完整
- 执行失败后的恢复

**核心问题：模型负责提出调用，运行程序负责实际执行，两者如何协作？**

## 四、MCP：工具和上下文如何标准化接入

### 4.1 MCP 的定位

- 连接 AI 应用与外部能力的协议
- 工具与数据接口的标准化
- 不同应用之间的能力复用

### 4.2 架构组成

- Host：承载 AI 功能的应用
- Client：与 MCP Server 通信的组件
- Server：提供工具、资源与提示模板的服务

### 4.3 核心能力

- Tools：可调用的操作
- Resources：可读取的上下文与数据
- Prompts：可复用的提示模板

### 4.4 连接与调用流程

- 初始化
- 能力发现
- 请求与响应
- 连接生命周期与异常处理

### 4.5 与 Function Calling 的关系

- Function Calling：模型提出结构化工具调用的机制
- MCP：外部能力的接入与通信协议
- 应用如何将 MCP 工具提供给模型

### 4.6 工程边界

- 身份认证
- 权限管理
- 服务隔离
- 外部内容可信度

**核心问题：如何让不同 Agent 应用复用同一组工具和数据接口？**

## 五、RAG：让回答建立在外部知识之上

### 5.1 基本原理

- 检索相关资料
- 将证据放入模型上下文
- 根据证据生成回答与引用

### 5.2 离线准备

- 文档解析与清洗
- 文档切分
- 元数据提取
- Embedding 生成
- 索引构建与更新

### 5.3 在线流程

1. 理解用户查询
2. 检索候选资料
3. 重排序与筛选
4. 组装上下文
5. 生成回答
6. 检查引用与证据支持程度

### 5.4 检索策略

- 关键词检索
- 向量检索
- 混合检索
- 元数据过滤
- 重排序

### 5.5 进阶方法

- 查询改写
- 多轮检索
- 按需检索
- 根据证据缺口追加检索

### 5.6 失败分析

- 没有召回相关证据
- 召回内容不相关
- 证据存在冲突
- 上下文信息不足
- 回答超出证据范围

**核心问题：是检索没找到证据，还是模型没有正确使用证据？**

- 召回率、速度与资源消耗的权衡

### 6.4 数据设计

- 向量与文本映射
- 来源、时间与版本

### 6.5 检索调优

- 切片大小与重叠

- 检索质量评估

### 6.6 生命周期管理

- 增量更新

- Embedding 模型迁移与重新索引

**核心问题：向量相似为什么不一定意味着答案相关或事实正确？**

## 七、长短期记忆：Agent 如何保持连续性

### 7.1 短期记忆

- 当前对话
- 任务状态
- 工具执行结果
- 当前工作上下文

### 7.2 长期记忆

- 用户偏好
- 历史事件
- 任务经验
- 持久化知识

### 7.3 记忆类型

- 事实记忆：已知信息
- 情景记忆：历史事件与经历
- 程序性记忆：方法、流程与经验

### 7.4 写入策略

- 什么信息值得记住
- 去重与归纳
- 来源与可信度标记
- 敏感信息处理

### 7.5 读取策略

- 相关性
- 时效性
- 重要性
- 访问权限
- 上下文预算

### 7.6 遗忘与纠错

- 过期信息处理
- 冲突记忆更新
- 错误记忆修正
- 用户主动删除

### 7.7 记忆与 RAG 的关系

- 记忆可以借助检索实现
- 记忆还需要写入、更新与遗忘策略
- 文档知识与个人记忆的管理差异

**核心问题：如何保留有用经验，又避免错误长期积累？**

## 八、上下文工程：把信息送到模型面前

### 8.1 上下文构成

- 系统指令
- 用户目标
- 任务状态
- 工具描述
- 检索证据
- 历史记忆

### 8.2 上下文预算

- 必须保留的信息
- 可以压缩的信息
- 可以外置的信息
- 为输出预留空间

### 8.3 管理方法

- 摘要与压缩
- 滚动窗口
- 按需加载
- 状态外置
- 分阶段上下文构建

### 8.4 信息优先级

- 权威来源
- 近期状态
- 关键约束
- 当前任务相关性

### 8.5 常见问题

- 上下文污染
- 摘要丢失细节
- 重复信息
- 指令冲突
- 无关信息占用预算

**核心问题：知识已经存储，为什么 Agent 仍然可能“想不起来”？**

## 九、多智能体编排：如何分工与协作

### 9.1 适用条件

- 任务可以独立并行
- 需要不同能力或专业视角
- 需要独立复核
- 分工收益能够覆盖协调成本

### 9.2 架构模式

- 主管与执行者
- 流水线
- 并行专家
- 任务交接
- 执行者与评审者

### 9.3 任务分派

- 明确职责边界
- 定义输入与输出
- 明确完成标准
- 分配工具与权限

### 9.4 通信与状态

- 消息协议
- 共享状态
- 独立上下文
- 信息同步与交接

### 9.5 结果整合

- 冲突处理
- 证据合并
- 重复结果去除
- 质量审核

### 9.6 协调成本

- 重复劳动
- 信息损失
- 延迟增加
- Token 开销
- 错误传播

### 9.7 退出与恢复

- 超时与失败接管
- 循环依赖处理
- 局部任务终止
- 全局任务完成判定

**核心问题：增加 Agent 后，收益是否超过协调成本？**

## 十一、综合实践：构建一个知识研究 Agent

### 11.1 项目目标

围绕一个主题检索资料，生成带引用的研究报告，并验证报告是否满足任务要求。

### 11.2 实现步骤

1. 建立最小 Agent 循环
2. 接入搜索与文档读取工具
3. 引入任务规划和验收标准
4. 建立文档索引与 RAG
5. 添加任务状态和长期记忆
6. 按需加入检索、写作、审核 Agent
7. 记录执行轨迹，评估质量与成本

### 11.3 交付物

- Agent 架构图
- 工具定义与调用流程
- 文档索引与检索流程
